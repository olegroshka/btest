## 4. Intensity Methodology

### 4.1 Method Definitions

**M-A — capex_assets_xsrank** (balance-sheet, US only)
- Formula: `CapEx / Assets`, four-quarter rolling, cross-sectionally percentile-ranked within ActorType per quarter
- Source: SEC EDGAR XBRL tag `PaymentsToAcquirePropertyPlantAndEquipment` + `Assets`
- Note: `CapitalExpenditures` XBRL tag has 0 filings (legacy, superseded). Must use `PaymentsToAcquirePropertyPlantAndEquipment`.
- BankCreditMapper (US-LC-FINS): cross-sectional percentile rank of YoY asset growth (4-period pct_change). Same cross-sectional approach as CorporateCapexMapper.

**M-B — return_12m_xsrank** (market-based, US or UK)
- Formula: rolling 12-month price return, cross-sectionally ranked per quarter
- Source: OHLCV (Yahoo Finance via btest)
- Used for: all UK universes (no EDGAR), and US universes in C4a homogeneous cross-geography comparison

## 7. Pipeline Evolution Notes

### How to extend the pipeline

**Add a new universe:**
1. Add universe CSV to `data/smim/universes/{UNIVERSE_ID}.csv` (columns: `ticker, sector`)
2. Run `uv run python scripts/smim_build_universes.py --universe {UNIVERSE_ID}` to fetch OHLCV

**Add a new EDGAR tag:**
1. Add the tag name to `XBRL_TAGS` list in `scripts/smim_fetch_edgar.py`
2. Re-run the script; it fetches only the new tag (CIK mapping is cached)
3. For alternative CapEx tags (G-13 fix): add `CapitalExpenditures`, `AdditionsToPropertyPlantAndEquipmentNet`, `PurchasesOfPropertyPlantAndEquipment` to the tag list, then re-run the CorporateCapexMapper to merge tags per actor

**Add a new FRED series:**
1. Add the series ID to `MACRO_SERIES` in `scripts/smim_fetch_fred.py`
2. For ALFRED vintaging: add to `ALFRED_SERIES` list as well
3. Re-run the script; existing series use cache, only new series are fetched

**Add a new GDELT actor:**
1. Add alias list to `ACTOR_ALIASES` dict in `scripts/smim_fetch_gdelt.py` (case-insensitive substrings matched against V2Organizations)
2. Note: `inst_fca_uk` uses `actor_BOE` as its GDELT proxy (BoE is the UK prudential regulator in GKG news)
3. Run `smim_fetch_gdelt.py --rebuild` to regenerate the weekly panel from existing daily cache (no re-download required)

### Key Architecture Decisions

**Why M-B (return_12m_xsrank) for UK, not M-A:**
SEC EDGAR covers only US-reporting entities. UK equities file with Companies House — a separate UK regulatory body. The Companies House data adapter was never built (G-4). Rather than block UK experiments indefinitely, Path B was adopted: 12-month price return cross-sectionally ranked is an economically meaningful proxy for relative investment/growth expectations. Decision confirmed 2026-03-28 (R4). Disclosure required in paper.

**Why UK-only OHLCV fallback (no US fallback for G-13):**
For US universes, M-A is the primary and homogeneous methodology. Applying M-B fallback for actors missing `PaymentsToAcquirePropertyPlantAndEquipment` would contaminate the cross-sectional ranking (demonstrated: ρ drops from 0.759 → 0.699 for US-LC-ENERGY when OHLCV fallback is applied). Those actors remain signal-only nodes. Fix path is to fetch alternative CapEx tags, not to mix methodologies.

**Why US-SC was trimmed:**
The Russell 2000 subset (US-SC, N=180 registry) had 48 high-missing actors (34% of intensity-computed actors) — post-2018 IPOs with sparse XBRL quarterly CapEx coverage. These actors would introduce systematic missing-data bias in C3 cross-capitalisation experiments. The trimmed universe (N=94, 0 high-missing) is the primary for C3. The full US-SC universe remains available for sensitivity analysis.

**Why dual-window ρ gate for US-LC-TECH:**
US-LC-TECH ρ_full=0.653 is below the 0.7 threshold but ρ_recent=0.750 passes. Root cause is genuine structural transformation in the tech sector 2010–2020 (shift from capital-intensive hardware to asset-light software/cloud), not a mapper or data quality issue. The dual-window gate (RP1.5) handles this correctly: the recent window (2020+) reflects the current economic regime that experiments target.

**GDELT Gen 3 canonical approach:**
Three generations of GDELT fetch approaches were tried. Gen 3 (daily GKG 2.0 CSV, one file per UTC day) is the canonical source. Gen 1 (weekly snapshot) was order-of-magnitude sparser. Gen 2 (DOC API) missed sector_energy/tech/financials entirely. The processed outputs in `data/smim/processed/gdelt_narrative*.parquet` are authoritative; raw Gen 1/Gen 2 files in `data/smim/raw/gdelt/` should be archived.
